feat(monitoring): #4 request_id + critical error log to KV

Adds observability for production debugging:

1. Request ID (X-Request-Id):
   - Generated per request (UUID v4) in dispatch()
   - Honored from client header if provided (capped at 64 chars)
   - Set on every response (success + error)
   - Available via get_request_id() for handlers to include in logs

2. Critical error log to KV:
   - log_error_to_kv() writes errors to KV with 7-day TTL
   - Key: error:{iso_ts}:{request_id} (lex sort = chronological)
   - Auto-truncates long errors (500) and field values (200)
   - Worker.fetch() logs unhandled exceptions
   - Router 404s are logged as warn
   - NEVER raises — monitoring never breaks the request

3. Admin endpoints to view errors:
   - GET /api/admin/errors?limit=N&severity=error|warn|info
   - GET /api/admin/error-stats (aggregated counts by severity)
   - Both require X-Admin-Key (existing admin auth)

4. dispatch() updates:
   - Generates X-Request-Id at start
   - Injects into all response headers
   - Logs 404s to KV (severity=warn)
   - Honors client-provided X-Request-Id for distributed tracing
